## 0. 이 문서 사용법

Claude Code에는 한 번에 한 Phase(§11)씩 구현을 지시한다. 진행 순서는 계획 → 구현 → §12 검증 → 커밋이다. 이전 Phase의 완료 기준을 통과해야 다음 Phase로 넘어간다.

- **요구사항 ID (v2)**: 커밋 메시지에 ID를 적는다.

  | 접두어 | 영역 |
  | --- | --- |
  | `CN` | 연결·소스 |
  | `VR` | 보기 렌더러 |
  | `AG` | 집계 타일 |
  | `WL` | 위젯 배치·크기 |
  | `IX` | 위젯 즉시 동작 |
  | `AD` | 항목 추가 |
  | `ED` | 편집 시트 |
  | `PR` | 속성 |
  | `RC` | 레시피 |
  | `SY` | 동기화 |
  | `KP` | v1에서 이어 가는 기능 |
  | `ST` | 설정 화면 |
  | `UX` | 화면 품질 규칙 |

  v1과 같은 뜻으로 이어 쓰는 ID는 `PF`(성능·안정성), `SEC`(보안), `A11Y`(접근성), `S25`(기기 최적화)다. `SEC-05`는 현행 `docs/PRD.md`가 'Room 캐시 자동 백업 제외'로 이미 쓰고 있어서(Phase 6에서 구현), v2의 새 보안 항목은 `SEC-06`부터 시작한다.
- **v1 ID**: `MV`, `WG`, `WS`, `WI`, `NS`, `EX`, `CAL`은 코드 주석에 남아 있다. 뜻은 보관본 PRD 기준이고, v2에서 어디로 이어지는지는 §1.3 표에 있다. v1의 `WI`(위젯 입력)와 헷갈리지 않게 v2의 위젯 동작은 `IX`로 쓴다.
- **현행 ID (Phase 6~9, `docs/PRD.md`)**: `HB`(해빗 트래커), `LD`(가계부), `DD`(디데이), `WX`(날씨), `EX-08·12·13`, `WG-10·11`, `VW-01~09`(노션 보기 읽기 전용 위젯)는 이미 구현됐거나 구현 중이다. 뜻은 현행 PRD 기준이고, v2에서 어디로 이어지는지는 §1.3 표에 있다. v2의 보기 렌더러는 이 `VW`와 겹치지 않게 `VR`로 쓴다.
- **우선순위**: P0 = 첫 사용 가능 버전(MVP) 필수, P1 = 다음 개선, P2 = 이후.
- **근거 표기**:
  - \[요구\] 사용자 지정(인터뷰 포함)
  - \[제약\] 플랫폼·API 사실

## 1. 배경과 방향 전환

v1은 노션 DB 일정을 월 달력과 위젯으로 보는 앱이다. 2주 실사용에서 안정성(콜드 스타트 247ms, 월 스와이프 느린 프레임 0.1%, 노션 대조 불일치 0)은 확인했다. 그런데 노션에서 실제로 쓰는 DB는 일정만이 아니다. 습관 체크, 지출 기록, 읽은 책, 할 일 보드처럼 모양이 제각각이다. v1은 '제목·날짜·완료·색' 네 속성만 매핑하는 구조라 이런 DB를 홈 화면에 올릴 수 없다.

v2의 목적은 분야를 가리지 않고, **노션에서 만든 어떤 DB든 홈 화면 위젯으로 조회·추가·수정하고 대시보드로 확인하는 것**이다 \[요구\].

### 1.2 v1의 한계와 Phase 6~9가 메운 것

아래 한계는 Phase 5(v1) 기준이다. 2026-10-19~22에 Phase 6~9가 일부를 **전용 구현**으로 메웠다. 습관(`HB`), 가계부(`LD`), 디데이(`DD`), 날씨(`WX`), 통합 탭 위젯(`WG-11`), 노션 보기 읽기 전용 위젯(`VW-01~09`)이다. 이것들은 종류(`data_sources.kind`)별 전용 매퍼·DAO·위젯이고, v2의 범용 속성·보기 층(CN·PR·VR)은 아직 없다. 그래서 아래 한계 중 '속성 매핑이 고정'과 '보기가 하나'는 여전히 범용으로는 맞다.

- 속성 매핑이 고정이다(제목·날짜·완료·색·정렬). 숫자·관계형·수식 같은 속성은 편집 시트의 '추가 속성'(select·status·number·url)으로만 일부 다룬다.
- 보기가 캘린더 하나다. 노션에서 만든 보드·표·차트를 홈 화면에 올릴 수 없다.
- 한 위젯은 '이번 달 일정'만 보여 준다. 여러 DB를 탭이나 구역으로 나눠 볼 수 없다.
- 설정 화면은 기능이 늘 때마다 한 화면 아래로 이어 붙여 왔다. 연결·DB·표시·알림·동기화·진단이 한 스크롤에 섞여 있다(부록 A-12).

### 1.4 핵심 시나리오

1. **일정·할 일**: 홈 화면 4×4 위젯의 '캘린더' 탭과 '상태 보드' 탭을 오간다. 보드 카드의 상태 칩을 눌러 '진행 중 → 완료'로 바꾼다.
2. **해빗트래커**: 4×2 위젯의 오늘 줄에서 '운동·독서·영어' 체크박스를 누른다. 아래 타일에 연속 달성 12일과 이번 주 달성률 86%가 보인다. 오늘 페이지가 없으면 첫 체크 때 만들어진다.
3. **가계부**: '점심 12000 식비'를 한 줄로 입력하면 금액·분류·날짜가 채워진 페이지가 생긴다. 이번 달 합계와 예산 진행 막대, 분류별 도넛이 바로 바뀐다.
4. **대시보드**: 화면 전체 크기 위젯에 오늘 할 일(리스트), 이번 주 지출(집계 타일), 독서 진행(차트)이 구역으로 쌓여 있다.
5. **오프라인**: 지하철에서 체크하고 지출을 적는다. 화면과 위젯은 즉시 바뀌고, 연결되면 노션에 순서대로 반영된다.

## 2. 목표, 비목표, 성공 지표

MVP(Phase 11)의 합격선은 다음 세 가지다.

- 레시피로 위젯을 2분 안에 완성한다.
- 위젯의 즉시 동작이 0.5초 안에 다시 그려지고 10초 안에 노션에 반영된다.
- 2주 실사용 동안 크래시 0건이다.

목표

- 노션 DB의 보기(표·보드·캘린더·리스트·차트, 2단계에서 타임라인·갤러리)를 홈 화면 위젯으로 그린다.
- 속성 22종을 모두 표시하고, API로 쓸 수 있는 속성은 위젯과 시트에서 편집한다.
- 한 위젯에서 여러 DB를 탭·구역·합쳐 보기로 다룬다.
- 앱 화면은 설정·편집 시트·위젯 구성·'더 보기' 전체 화면만 둔다. 주 사용 화면은 홈 화면 위젯이다.

비목표

- 1×1·2×1 위젯. 정보 단위 하나도 담기 어렵다.
- 실시간 반영(노션 웹훅). 공개 HTTPS 서버가 필요하다(§13).
- 다중 사용자·OAuth·팀 공유. 혼자 쓰는 내부 연결 토큰 앱이다.
- 페이지 본문 자유 편집. 본문은 읽기와 끝에 메모 덧붙이기만 한다(ED-06).
- 노션 보기 필터·정렬의 앱 내 편집. 필터는 노션에서 고치고 앱은 그대로 따른다.
- 노션 '양식(form)'·'지도(map)' 보기. 양식은 위젯 입력 양식(AD-02)으로, 지도는 장소 속성을 눌러 지도 앱을 여는 것(PR)으로 대신한다.
- '확인(verification)' 속성. 위키 DB 전용이다.
- 노션 DB 스키마(속성·옵션) 생성·변경. 단, 선택·다중 선택에 새 옵션 이름을 쓰는 것은 노션이 허용하므로 한다.
- Play 스토어 배포, iOS, Wear OS.

## 4. 핵심 개념

```text
연결(토큰 1개)
 └─ 소스 = 노션 DB의 data source (여러 개, 스키마 전체를 Room에 저장)
     └─ 보기 = 노션 보기(표·보드·캘린더…) + 위젯별 덮어쓰기(표시 속성·순서·행 수)
위젯(홈 화면 1개)
 └─ 배치: 단일 | 탭 | 섹션 | 합쳐 보기 | 노션 대시보드(2단계)
     └─ 섹션: 보기 | 집계 타일 | 프리셋 줄 | 액션 버튼 줄
레시피 = 위의 구성을 미리 짜 둔 틀(일정·할 일, 해빗트래커, 가계부, 갤러리 기록)
프리셋 = 새 항목에 넣을 값 묶음(예: '점심 · 식비 · 12000')
액션 = 기존 항목의 속성을 바꾸는 묶음(예: '내일로' = 날짜 +1일)
```

- **보기 우선**: 어떤 항목이 보기에 속하고 어떤 순서인지는 노션의 보기 쿼리 결과를 따른다. 그래서 노션 보기와 위젯 목록이 같다. 항목의 속성 값은 Room의 페이지 캐시에서 읽는다.
- **덮어쓰기**: 위젯마다 표시 속성·순서·행 수·보드 열 순서를 덮어쓸 수 있다. 필터·정렬은 노션 보기를 그대로 쓴다(비목표).

## 7. 아키텍처

모든 화면과 위젯은 Room만 읽고, 노션 통신은 동기화 모듈만 한다(불변 규칙). v2에서도 이 구조는 바뀌지 않는다. 데이터가 '일정'에서 '페이지 + 속성 값'으로 일반화된다.

현행 Room 버전은 v15이다(v14 보기 쓰기, v15 표지·읽은 비율). Phase 10은 v16 한 번으로 `source_schemas`(소스 스키마 전체)·`view_writes.baseValue`·`sync_log.requests`·`view_rows(pageId)` 인덱스를 더한다. 아래 표는 v2가 **더하는** 것의 장기 목표이고, `pages`·`views`·`view_items`는 Phase 12 이후 재검토한다(§14).

- DataStore(암호화): 토큰만(SEC-01).

### 7.3 이전 (현행 → v16)

- 유지: 등록 DB와 토큰, v1 매핑(→ `calendarDefaults`), 위젯 테마·투명도·배율.
- 유지: Phase 6~9의 표 전부와 `data_sources`의 새 열, 앱 상태 표(`dday_pins`·`ledger_dup_keeps`, 복구 KEEP 목록)와 `widget_configs`의 새 열(`selectedTab`·`hideAmounts`·`ddayPageId`·`showWeather`·`viewId`).
- 남은 아웃박스: 기존 매핑 열로 새 형식(속성 ID → 값)으로 바꾼다. 바꿀 수 없는 행은 충돌 기록에 남기고 버리지 않는다.
- 일정 캐시: 지우고 다시 받는다(PF-09의 '캐시만 지우고 재동기화'와 같다). 습관 기록·거래 행도 `events`에 있어 같이 다시 받는다. 대기 중인 아웃박스와 앱 상태 표는 지우지 않는다.
- 옛 위젯 3종: 'v1 호환 캘린더 레시피'로 자동 변환을 시도하고, 실패하면 '다시 설정' 상태로 둔다.

### 8.5 보기 읽기 경로와 9-A 실측 (2026-10-21, 현행 Phase 9)

실기기·실제 DB 3개·보기 10개(table 3, list 1, calendar 3, gallery 1, timeline 1, board 1)로 확인했다. 근거는 `docs/plans/phase-9.md`의 9-A 결과이고, 구조 픽스처는 `core/notion/src/test/resources/fixtures/views_probe_shape.json`(값을 가림)이다.

- `GET /v1/views?data_source_id=`는 `{object, id}`만 준다. 이름·유형·설정은 `GET /v1/views/{id}`로 읽는다. 설정은 `type`·`filter`·`sorts`·`quick_filters`·`configuration.properties[]`(`property_id`·`property_name`·`visible`·`width`)다. board·calendar·timeline·chart 등 **유형별 `configuration`의 나머지 키는 아직 실측하지 못했다**(`JsonObject`로 받고 알려진 키만 읽는다).
- `POST /v1/views/{id}/queries`의 `results`는 `{object:"page", id}`뿐이고 값은 주지 않는다.
- **기본 경로는 데이터 소스 쿼리**다. 보기 `filter`와 `quick_filters`(`{속성 id: {타입: 조건}}`를 `{property, 타입: 조건}`으로 바꿔 `and`로 묶음), `sorts`를 그대로 넣는다. 보기 쿼리와 id·순서를 비교하면 **10개 중 9개가 완전히 일치**했다. `quick_filters`를 합치기 전에는 4개가 달랐다(빠른 필터가 `filter`에 들어 있지 않다).
- 알려진 불일치 1건: board 보기(빠른 필터 `relation is_empty`)는 보기 쿼리가 0행, 데이터 소스 쿼리가 100행이었다. 같은 빠른 필터의 calendar 보기는 일치했다. 원인은 확인하지 못했다.
- `GET /v1/views/{id}`가 `Validation`(400)을 준 보기가 2개 있었다. 종류를 알 수 없어(목록 응답에 종류가 없음) '지원하지 않는 보기'로 건너뛴다. 대시보드·양식 보기일 가능성은 있으나 확인하지 못했다(§8.2는 대시보드의 `data_source_id`가 null이라고 적는다).
- 호출 9회(DB 3개 × 목록·보기·쿼리)가 3.9초 걸렸다.
- 결정: SY-02는 위 기본 경로를 따른다. 보기 쿼리는 진단 '노션과 비교'의 대조용이다. §2 '보기 일치' 지표의 알려진 예외는 board + relation 빠른 필터 1건이다.
